# Solution Outline Methodology

The Solution Outline is the architecture-level narrative artifact that consolidates
Objectives and validated diagrams into a structured architectural description.

It must:
- follow the approved template exactly
- remain architectural and descriptive
- reflect only supported content from Objectives and diagrams
- avoid implementation and deployment detail
- preserve open assumptions and unresolved points where applicable

It must not:
- invent requirements, scope, systems, or integrations
- introduce unsupported technologies
- resolve ambiguities not already supported by authoritative inputs
- include empty sections

All changes follow:
Generate → Evaluate → Patch → Recheck → Final Review
