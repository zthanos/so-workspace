# Decision Identification Guidelines

ADRs should capture decisions that significantly influence architecture.

Examples include:

Integration patterns
API gateway usage
Event-driven architecture adoption
Data storage architecture
Security architecture
Identity and authentication approach
Deployment model

ADRs should NOT capture:

Minor implementation details
Low-level code decisions
Temporary workarounds
Operational procedures

ADRs should focus on decisions that impact:

system structure
integration boundaries
data architecture
scalability and resilience
security posture
