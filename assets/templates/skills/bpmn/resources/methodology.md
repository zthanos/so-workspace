# BPMN 2.0 Methodology

Use BPMN when the user needs a formal business process model with:
- clear responsibilities
- participant boundaries
- gateway semantics
- explicit cross-participant communication

Prefer BPMN over a basic flowchart when:
- more than one participant is involved
- the process has approvals, handoffs, or exception paths
- message exchange matters
- responsibility boundaries must be visible

Do not use BPMN to represent:
- code structure
- API topology
- deployment architecture
- low-level UI click paths
