# BPMN Anti-Patterns

Avoid these mistakes:

- using generic flowchart shapes instead of BPMN semantics
- crossing pool boundaries with sequence flow
- using message flow inside one pool
- omitting pools in a collaboration process
- unlabeled exclusive or inclusive gateway branches
- packing too many tasks into one lane without spacing
- mixing architecture components and BPMN tasks on the same page
- naming tasks with technical implementation jargon when business language is expected
- drawing exception paths that are impossible to distinguish from the happy path
